# AGENTS.md — Life Tracker

Monorepo for a personal life-tracking app: web frontend, Android (Expo) mobile
app, Go backend API, Chrome extension, shared packages, and deployment.

## Repository layout

- `frontend/` — Next.js (App Router) web app: Tailwind v4 + shadcn/ui, Prettier.
  Feature folders under `app/<feature>/` (`components/`, `modal(s)/`, `hooks/`, `views/`).
- `apps/mobile/` — Expo / React Native Android app (expo-router, NativeWind v4).
  `app/` routes, `components/ui/` primitives, `components/<feature>/` folders.
- `backend/` — Go API (Gin + GORM + MongoDB, JWT). Domain-driven:
  `internal/domain/<name>/{controller,service,repository,model,dto,routes}`.
  Has its own `CLAUDE.md` — read it for backend work.
- `packages/shared/` — code shared by web + mobile: `services/`, `types/`, `lib/`
  (incl. `theme-colors.ts`, `activity-templates.ts`), i18n (`messages/{en,es}.json`,
  `language-context.tsx`). No build step; consumed from source.
- `chrome-extension/` — Manifest V3 screen-time extension (plain JS).
- Root `docker-compose.yml` — the single compose file (api + databases + web;
  observability and load-test stacks are profiles), with `nginx/` configs and
  deploy/migrate `scripts/`.
- `loadtest/` — k6 suite (own Makefile).
- `docs/` — per-area documentation (`frontend.md`, `mobile.md`, `backend.md`,
  `architecture.md`, `ci-cd.md`, `testing.md`, …).
- `Makefile` (root) — single entry point for all commands; `make help` lists them.
- `styles.md` — cross-platform UI contract.

## Workspaces & package manager

- npm workspaces include **only** `apps/mobile` + `packages/shared`.
- `frontend/` is deliberately outside the workspaces (self-contained for
  CI/Docker): run `npm install` separately inside `frontend/`. Ignore the stray
  `pnpm-lock.yaml` there.
- Both platforms consume shared code via the `@shared/*` alias: web through
  tsconfig paths; mobile through the workspace-aware `metro.config.js` (don't
  simplify it — Metro breaks without `watchFolders` on the repo root).

## Before starting

- **UI / styling / component work:** read [`styles.md`](styles.md) first. It defines
  the cross-platform token source of truth (`packages/shared/src/lib/theme-colors.ts`),
  reuse rules (shadcn on web, `apps/mobile/components/ui` on mobile), and the
  baseline visual look.
- Feature-specific context: [`docs/frontend.md`](docs/frontend.md),
  [`docs/mobile.md`](docs/mobile.md), [`docs/backend.md`](docs/backend.md),
  [`backend/CLAUDE.md`](backend/CLAUDE.md).
- Run modes (`make dev` / `dev-container` / `dev-full` — one at
  a time, `make stop` between switches): [`docs/getting-started.md`](docs/getting-started.md),
  [`docs/deployment-modes.md`](docs/deployment-modes.md).

## Commands

- Root Makefile is the entry point: `make dev`, `make stop`, `make test`
  (backend), `make code-check` (gofumpt + golangci-lint), `make mobile` /
  `mobile-rebuild`, `make setup` (copies `.env.example` → `.env`).
- `frontend/`: `npm run dev`, `lint`, `type-check`, `format` (Prettier — CI gate).
- `apps/mobile/`: `npm run start`, `type-check`, `export:android`.
- Never read or commit `.env*` contents.

## Ground rules

- Reuse existing components and utilities before creating new ones.
- Keep business logic in `packages/shared` (services singletons); platform code
  stays in its app.
- Match existing conventions per app; don't refactor unrelated code.
- **Conventional Commits PR titles are release-critical** (release-please
  computes versions/changelog from them; a PR-title workflow enforces the
  format).
- Backend schema changes: add versioned SQL migration pairs in
  `backend/internal/database/migrations/` (auto-run on start); GORM is
  ORM-only — no AutoMigrate.
- Theme tokens: edit `theme-colors.ts` once; keep `apps/mobile/tailwind.config.js`
  and web CSS vars in sync (see `styles.md`).

## Gotchas

- Mobile entry **must import `lib/storage-init.ts` first** — it installs the
  storage adapter + API URL before shared services init. Import order matters.
- `app/finance/` is the single finance page (tabs); `finance/dashboard` and
  `finance/transactions` are redirect shims — don't build on them.
- `apps/mobile/android/` is generated by expo prebuild (git-ignored).
- `frontend/out/` static export is committed on purpose.
- Web env is injected at runtime via `/env-config.js` (`frontend/inject-env.sh`),
  loaded in `app/layout.tsx`.
